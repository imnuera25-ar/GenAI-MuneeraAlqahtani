# My Final Project

## Project Name
IT Request Organizer Assistant مساعد تنظيم تقنية المعلومات

## Idea Selected

مساعد ذكي يستقبل طلبات دعم تقنية المعلومات المكتوبة بشكل عشوائي (رسائل واتساب، إيميلات، ملاحظات مكالمات) ويحوّلها إلى جدول منظم يحتوي على: تصنيف الطلب، الأولوية، الجهة المسؤولة، الإجراء المقترح، والمعلومات الناقصة.
الهدف: تقليل وقت فرز الطلبات، وتوحيد طريقة تصنيفها، وضمان ألا يضيع أي طلب مهم


## Problem Statement

الطلبات تصل من قنوات متعددة وبصياغات غير واضحة.
فريق الدعم يقضي وقتًا طويلًا في قراءة الطلبات وتصنيفها يدويًا.
الأولوية تختلف من موظف لآخر، فقد يتأخر طلب عاجل.
كثير من الطلبات تفتقد معلومات أساسية (الجهاز، رقم الموظف، وقت حدوث المشكلة) فتحتاج مراسلات إضافية.

## Target Users
فرق الدعم الفني ومشرفو تقنية المعلومات في الجهات الحكومية، ممن يستقبلون طلبات دعم متنوعة من الموظفين ويحتاجون فرزها وتحديد أولوياتها بسرعة.

## R-C-T-F Prompt
Role:

أنت منسق دعم فني (IT Service Desk Coordinator) خبير في فرز وتصنيف طلبات

تقنية المعلومات داخل جهة حكومية.

Context:

سأعطيك طلبات دعم فني مكتوبة بشكل غير مرتب وقد تكون مختلطة بين العربية

والإنجليزية. فريق الدعم مقسّم إلى: الشبكات، الأجهزة، البرمجيات والحسابات،

الأمن السيبراني. مستويات الأولوية:

- عاجلة: توقف عمل أو تأثير على عدة موظفين أو شبهة اختراق.

- عالية: تعطل عمل موظف واحد بدون بديل.
- متوسطة: مشكلة مزعجة لكن يوجد حل بديل.

- منخفضة: طلب عادي أو تحسين.

Task:

1. حلّل كل طلب على حدة.

2. صنّفه (شبكات / أجهزة / برمجيات وحسابات / أمن سيبراني / أخرى).

3. حدد الأولوية مع سبب مختصر.

4. اقترح الإجراء الأول للفريق.

5. اذكر المعلومات الناقصة التي يجب طلبها من الموظف.

6. إذا كان الطلب يحتوي على أي بيانات حساسة (كلمة مرور، رقم هوية)،

   نبّه عليها ولا تكررها في المخرجات.

لا تخترع معلومات غير موجودة في الطلب. إذا كان الطلب غير واضح اكتب "غير محدد".

Format:

جدول بالأعمدة التالية:

| # | ملخص الطلب | التصنيف | الأولوية | سبب الأولوية | الجهة المسؤولة | الإجراء المقترح | معلومات ناقصة |

ثم بعد الجدول:

- "ملخص سريع": عدد الطلبات حسب الأولوية.

- "تنبيهات": أي بيانات حساسة أو طلبات تحتاج تصعيدًا فوريًا.


## Sample Input
1. السلام عليكم، الانترنت عندنا في الدور الثالث واقف من الصبح ومحد يقدر يشتغل
2. ابغى اغير الماوس تبعي، عالق شوي
3. Outlook مايفتح معي وطلع لي خطأ، بس مو مستعجل
4. وصلني ايميل يقول حسابي بينغلق اذا ما دخلت على الرابط وحطيت الباسورد، دخلت عليه وحطيت باسوردي
5. ممكن تثبتون لي برنامج Adobe Acrobat على جهازي؟

## Safety Checklist

لا أدخل أسماء موظفين حقيقية أو أرقام هوية أو بيانات اتصال في الأداة.
لا أدخل كلمات مرور أو روابط داخلية أو عناوين IP حقيقية.
أستخدم بيانات وهمية أو مجهولة الهوية عند التجربة.
أراجع التصنيف والأولوية بشريًا قبل اعتمادها، خصوصًا الطلبات "العاجلة" و"الأمن السيبراني".
أتحقق أن المساعد لم يخترع معلومات غير موجودة في الطلب الأصلي.
أعتمد سياسة الجهة في استخدام أدوات الذكاء الاصطناعي.
أعتبر المخرجات مسودة مساعدة وليست قرارًا نهائيًا.

## Reflection
تعلمت أن جودة المخرجات ترتبط مباشرة بوضوح الـ Prompt، وأن تحديد الدور والسياق ومستويات الأولوية يجعل النتائج أكثر اتساقًا. ساعدني الذكاء الاصطناعي في تحويل طلبات عشوائية إلى جدول واضح يمكن للفريق العمل عليه مباشرة. لو توفر وقت إضافي سأربط المساعد بنظام تذاكر (Ticketing System)، وأضيف قواعد أدق للتصنيف حسب سياسة الجهة، وأجرب المساعد على عدد أكبر من الحالات لقياس دقته. اتبعت احتياطات حماية البيانات باستخدام بيانات وهمية فقط، ومراجعة المخرجات بشريًا قبل اعتمادها
